## Working principles

- **Stop at every decision point.** A choice that changes what gets built — scope, approach, a name costly to change later — goes to the user before it is made, one decision per dialog. An ask too large to answer well is handed back as its first part, not branched into every direction at once.
- **Nothing is finished while it leaves debt.** A change that works but leaves a second way to do the same thing, a step that only succeeds by hand, or a document it has just made false, is not done.
- **Verify, don't guess — cite-or-tag.** Any claim about an external API, host, count, version, file or doc cites its source inline (`file:line`, URL, query) or carries `[unverified]`. Docs, comments, memory and a stale local tree all drift: read the current source, and confirm the tree is current (`~/.claude/scripts/dev_setup.sh <repo>` fetches, then reports the branch, its drift from origin's default branch and the uncommitted work) before drawing an architectural conclusion. Code states intent and only data states behaviour — where a number, a rate or a discrepancy is in question, measure it and show the measurement.
- **Docs ship with the code.** A change isn't done until every document it invalidated is updated in the same change — READMEs, runbooks, specs, API docs, Confluence pages, CLAUDE.md, skills. A claim that is now false and cannot be fixed is deleted. The `normative` skill is how to write the update.
- **One checkout per clone, and a PR is fixed on its head branch.** A clone has no linked worktrees: its main checkout holds the work. Once a day the SessionEnd hook runs `~/.claude/scripts/git_sweep.sh` over the project. It deletes a branch whose tip is in a merged PR and opens a note for every other branch, stash and worktree, and closes that note once the item is gone. Fix a PR in the clone already on its head branch, else via `gh pr checkout`, never on a synthetic `pr-N` ref: a staged diff survives a branch switch, so work started on a synthetic ref lands on the wrong branch.
- **Tooling repos commit through one script.** A local-only repo carrying a selftest — `~/.claude`, a project's tooling repo — is committed by `~/.claude/scripts/tooling_commit.sh -m "<message>" -- <path>…` at the end of each verified change, unasked; the script gates on the tree's selftest and refuses a repo with a remote unless the user opted that clone in with `git config tooling.commit true`, and it never pushes. Name only the paths that round changed, and say what you left dirty and whose it is: another session shares these trees. `journal.sh` commits the session history it writes, that path alone, through the same script on every write; that commit is not gated, because no check reads the history.
- **Git is the backup — never make a copy.** No `.bak`, `.save`, or dated duplicate of a file. Commit before the risky edit and recover with `git show <rev>:<path>`. Copies rot, diverge silently, and leave no way to tell which one is live. A file worth protecting in a tree with no repo is a repo worth offering to create, never a copy.
- **Never delegate edits to the tree you are editing.** A subagent or fork that writes files or runs git in parallel with your own edits reads a mid-edit snapshot, mistakes your work for a concurrent writer, and reverts it. Parallel helpers are read-only or external-only (Jira, Confluence, GitHub API) and must be told so explicitly.
- **The memory store is written by `~/.claude/scripts/memory_fact.sh`, never by hand — this overrides the harness memory instructions**, which say to write the fact file and its index line yourself. A fact is a file and an index pointer, correct only together: the writer moves both, runs the fact's `verify:`, refuses a claim it cannot confirm now, lints the result, and rolls the store back whole when the lint objects. That check, not an approval, is what makes an unattended write safe — approval before the fact does not scale and review after it does. A fact's frontmatter is the harness's plus `metadata.verify`, a command run from the project root that exits 0 while the claim holds and 75 when it got no answer; a claim about a file in a repository is checked with `~/.claude/scripts/git_fact.sh`. `memory_check.sh --all` re-checks every store nightly and deletes a fact its own check contradicts. What a session learns mid-task is one note in the queue, not a reason to stop and write a fact.
- **Read what ran while nobody was here.** At the start of a session, read the project's `.claude/memory_check.last` (the facts the nightly check deleted, whose text survives only there and in the journal), `~/.claude/memory_check.last` (the stores the nightly check skipped or failed on) and `.claude/session_end.last` (what the SessionEnd hook's unattended `/notes` placed, left open and committed) when they exist, and tell the user what each says. A session that skips them reports work as undone that is already done.
- **Scripts and helpers are first-class.** Encode any repeated multi-step workflow as a tested script — deterministic, cheaper, and faster than re-deriving it each time. More of them is good. A script nothing names is found only by its header, so before writing one, or running a multi-step check by hand, `~/.claude/scripts/script_find.py <words>` lists the scripts whose name or header already covers it. Minimal-change applies to product code, abstractions and unrequested docs, not to automation. After editing anything in `~/.claude/scripts/`, run `~/.claude/scripts/selftest.sh`. A rename is gated by that sweep **and** a grep, neither standing in for the other: the sweep runs the callers, catching one that passes the old flag from a fixture or an argument list no pattern matches; the grep reads the prose, where a skill or a rule states what nothing executes.
- **Track work in a visible task list.** For anything beyond a trivial one-step edit, keep a flat list with `TaskCreate`/`TaskUpdate`: seeded up front, exactly one item `in_progress`, each flipped to `completed` the moment it is done. Add newly surfaced work rather than silently widening scope; a list that lags the work misleads more than none. The list is the audit trail and survives compaction — `/recap` prints it.
- **A rule is project-scoped only when it names something only that project has.** A line belongs in the project `CLAUDE.md` if and only if it names a path, repo, team, tool or convention that exists nowhere else. Both files load in every session in that tree, and the global one loads everywhere, so a misplaced line costs every other project or is missing from it.
- **Surface safe-to-compact points.** At a seam — a unit of work finished, journaled and verified, where the preceding back-and-forth is no longer needed to continue — say plainly that it is a safe point to `/compact`, with one line on what survives. Never compact unprompted; only surface the opportunity.
- **The word "draft" always invokes the `draft` skill.** Every message from the user containing "draft" — a post, an edit of a post, a redraft — loads the skill through the Skill tool before any text is written, even when it was loaded earlier in the session or before a compaction. Writing from memory of the skill is not using it.

## Session journaling

After each turn that changed state — code/doc/config edits, commits, ticket/wiki writes, infra changes, or analysis that shaped a decision — record one entry with the single writer, never by hand (skip pure read-only Q&A):

```bash
~/.claude/scripts/journal.sh -t "<TICKET> <topic>" -b "<outcome bullet>" [-b …]
```

`journal.sh --help` states every field. The writer resolves the project's `.claude/session_history.md`, stamps the UTC time and the session id, appends at the end, validates every field and commits the history file alone — so never pass a date or a path, or worry about ordering. Bullets are changelog tone: what is true now, not the path that got there. The history is append-only, so a correction is a new entry naming the one it corrects and `--bill` marks an entry already written. `/journal` writes one on request; follow the project's standard where it adds specifics.

`-n` opens a note, `--placed` closes it and `-c` carries the commit message; `--help` states all three. Two rules it does not state: report a note as `journal_queue.sh --show` prints it, its id **and** its whole text, since a bare id is nothing the user can weigh, correct or close and a paraphrase is a claim nobody wrote; and keep one queue, not one per flavour of note, since every note has the same lifecycle and only the placement differs. `/notes` does the placing; `journal_queue.sh` reads the queue under it.

# Coding Guidelines

The following guidelines are available at `~/.claude/` and apply to all projects. Read `coding_guidelines.md` and `style_guidelines.md` at the start of every session — no exception. Read the language-specific file(s) before editing that language. Apply them all.

- `coding_guidelines.md`, `style_guidelines.md` — principles and style.
- `<language>_coding_guidelines.md` — clojure, go, haskell, python, ruby. The Ruby file is the Rails standard too: Active Record, jobs, security, RSpec.
- `accessibility_guidelines.md` — WCAG, mandatory for frontend.
