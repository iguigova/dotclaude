My Claude Code setup

Instructions get forgotten.
Code doesn't.

Claude Code is an AI that writes code from a terminal. On a long task it loses hold of the rules I gave it. So small programs keep the rules for it, and they can say no.

A hook is a small program Claude Code runs around each of the assistant's steps. It can refuse the step.

A day with it

  1. 09:00A session starts

    Starts blank. Overnight never happened.

    Reads what ran overnight, and tells me.

  2. 10:30"Done. Shall I commit?"

    I skim, type "sure", and something I never read is committed.

    A question in prose is sent back. It asks again in a dialog, and waits.

  3. 11:15A command is blocked

    It finds another way around.

    Every other step is refused until I answer.

  4. 13:30It's about to edit code

    Did it read my coding guide today? Nobody checks.

    The edit is refused until it has read the guides, whole.

  5. 14:00It commits a change

    The tests pass, so it's done.

    The tests have to catch bugs planted in the change.

    1. A change
    2. Every script's own testseach script tests itself
    3. Bugs plantedon each changed line, like < into <=
    ✓ Every bug caughtCommitted.
    ✗ One survivesNothing is committed. Back to the tests.

  6. 17:00It spots something off-task

    Mentions it once. Then it's gone.

    Writes a note that waits for me. I really like this one.

Even the instructions have tests

A skill is a page of instructions the assistant picks up when a request fits. Instructions are code too, so they get tests. Each case runs in a fresh session, a few times, and the majority decides.

Skills fire when they should “log my time” ✓ fires “add a timing log line to the deploy script” stays quiet Change a skill's description, and its cases run before the commit.
It still sounds like me Texts I liked, and texts I didn't, like “I've built pieces other developers stand on.” ✗ not me A fresh reviewer has to judge every one the way I did.

Where it comes from

All of it grows from one short file, my credo. It loads into every session. Its mission is one line: “Build simple systems people can trust.”

Checking matters more than storing.So every fact carries its check, and every script its tests.
Removing is generous, not violent.So a fact that fails its check is deleted, not flagged.
Point, don't copy.So a rule names the script that enforces it.
Never get ahead of the evidence.So a check has three answers, and "no answer" deletes nothing.

Take what fits

It fits one person: me. It says no exactly where I tend to slip. But the patterns travel, it's MIT-licensed, and each piece needs little of the rest.

  • credo.md
    Write your own. One line in your CLAUDE.md loads it everywhere.
  • ask_gate.py
    If you've ever said "sure" to a question you didn't read.
  • git_fact.sh
    A fact is only worth keeping with a command that can prove it wrong.
  • skill_trigger_test.py
    If you've ever edited a skill and it quietly stopped firing.

What it can't do yet

  • Nothing measures the outcome. The tests show each part works. Nothing shows the whole makes my work better.
  • Two sessions in one folder can trip over each other's half-finished edits.
  • The 04:30 check runs only while I'm logged in. A missed night runs at my next login.
