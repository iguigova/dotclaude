Don't take my word for it

My Claude Code setup keeps only what it can check. So does this page.

The idea

I don't want an assistant that remembers a lot. I want one whose memory I can trust.

So nothing gets kept without a way to check it. Not a fact, not a rule, not a number on this page. Each sentence below that makes a claim names a file and the words it should find there. When this page loads, your browser reads those files and looks. Press any mark to see the line it found.

Words alone are a modest check: they show the file says what the sentence says, not that the code does it. So where a self-test proves the behaviour, the claim names that test too, and GitHub runs every self-test on each push. The second line at the top says how the last run went.

The loop

  1. 1 · rule A rule says what to do, and anything done twice becomes a tested script.
  2. 2 · test One command runs every script's own self-test, and GitHub runs it on every push.
  3. 3 · commit A change is committed only when every test passes, and never pushed by the script.
  4. 4 · journal Each turn that changed something gets an entry, from one writer.
  5. 5 · note What a session notices becomes a note, and each note is done, dropped or kept open.

↺ And the next session starts by reading what ran while nobody was here.

Try it

A memory fact is one claim and a command that checks it. Here's one about this repo. Change the words and run the check. Your browser does what git_fact.sh does: it reads the file and looks for the words.

name: credo-removing
claim: the credo says "Removing is generous"
verify: git_fact.sh dotclaude main credo.md 'Removing is generous'

Memory

There are three answers a check can give, and each one does something different.

  • 0, it holds. A fact is only written when its check passes the day it's written.
  • 1, it doesn't. A fact its own check contradicts is deleted, file and index line.
  • 75, no answer. Nothing is learned, and nothing is deleted on a maybe.

While I'm away

  • Every night at 04:30, every fact is checked again, and a night the machine missed is caught up.
  • A session starts by hearing how many notes are open, and the three oldest.
  • When it ends, what it noticed is placed without me.
  • Once a day, a branch whose pull request merged is deleted.
  • Nothing reaches this public repo if it looks like a key, a token or a real email.

Why

Even what I believe is checked, against my credo.

Checking matters more than storing.
No fact without a check.
Removing is generous, not violent.
A struck-out claim on this page is a kindness. You'd rather know.
Point, don't copy.
This page copies nothing. It points at the files and reads them.
Never get ahead of the evidence.
A file that can't be reached proves nothing, so its claim says "no answer", not "false".

Known gaps

  • The nightly timer only runs while I'm logged in, so a missed night runs at my next login, not at 04:30.
  • A claim with no self-test beside it is checked on its words alone. A file can say the right thing and do the wrong one.
  • GitHub's answers count toward a limit of 60 an hour for each reader. Past it, the live numbers and the run show a dash or no result, never a guess.
